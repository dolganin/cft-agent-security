# A02 positive source catalog

This is a source-reviewed catalog at Juice Shop commit
`5658473cf8814459bf89000ce373b20ed0b4eb37`, not A04 frozen ground truth or runtime
Evidence. A01 protocol/lock are unchanged. No negative controls or scored runs exist.

| Artifact | Role |
|---|---|
| `candidates.generated.yaml` | 116 unreviewed challenge candidates, metadata/annotation anchors, source/test references, source manifest and bounded Express map |
| `positives.reviewed.yaml` | 27 source-reviewed independent root causes, multiple anchors, prerequisites, criteria, eligibility and A01 split |
| `excluded.yaml` | Disposition of the other 89 challenge candidates; reasons and represented cases; never negative labels |

The extractor reads tracked source bytes only, verifies the exact commit and each
Git blob against the checkout, and never runs target scripts. It combines upstream
challenge metadata, actual `vuln-code-snippet` comments, source/test references and
the unchanged `build_express_source_map`. The existing bounded map omits dynamic
Finale endpoints and client routes; reviewed anchors record these explicitly.
Candidates and challenge counts do not establish vulnerabilities by themselves.

```bash
python -m evaluation.benchmark_protocol
python -m evaluation.positive_catalog extract --target artifacts/benchmark-target/juice-shop
python -m evaluation.positive_catalog validate --target artifacts/benchmark-target/juice-shop
python -m pytest tests/test_a02_positive_catalog.py -q
```

`extract` writes only the generated file. It never creates or approves reviewed
cases or rewrites exclusions. To compare generated bytes without touching the
checked-in artifact, pass `--catalog artifacts/a02-regenerated`. Catalog output
must stay outside the target checkout. `validate` regenerates candidates in memory,
checks source ranges/file and region digests/tokens, challenge/provenance/service/
HTTP references, root-cause collisions and the locked A01 split. It reports only
catalog counts, never precision/recall/FPR.

One selected record represents one root cause. `primary_candidate` is a convenient
upstream index reference, not a one-challenge/one-vulnerability assertion. Additional
challenge keys can be effects, dependencies or environment guards. Only exclusions
explicitly marked `duplicate_root_cause` mean the reviewed same-cause relationship;
Docker-disabled XSS guard scenarios are not silently reclassified as NoSQL/SSTI
duplicates. No independent positives were added for related login personas,
schema enumeration or FTP backup filenames.

The SQL login/search sinks are independent. Review ownership and JSON query-operator
acceptance are independent despite sharing an update handler: fixing scalar input
does not enforce ownership, and identity enforcement does not establish scalar-only
selector behavior. Public sensitive directory publication is conservatively one
group with FTP/keys/logs anchors; filename validation-before-canonicalization is
another root cause. Historical v1's three listing cases remain untouched.

Source regions use LF-joined physical lines plus a trailing LF for region SHA-256;
file SHA-256 binds the raw tracked bytes. Coordinates are one-based and inclusive.
`required_tokens` are bounded source assertions, not a matcher or execution payload.
`relations` use zero-based source-anchor indices; they describe the review and are
not a new caller/helper resolver. HTTP paths are registration patterns, not invented
scanner anchors. DOM XSS has an explicit client route and no fictitious HTTP fragment.

21 cases have conditional default-Docker source eligibility; this does **not** mean
the current Pentester supports them, has execution permission, or confirmed them.
6 remain detection-only: guarded NoSQL tracking, API stored XSS, profile expression
eval, ZIP traversal, XML external entities, and SSRF without an approved observation
fixture. Safety mode is never relaxed. Upstream exploit tests were inspected only;
their xit/Docker guards and unsafe payloads are not execution instructions.

DEV/HOLDOUT comes solely from `split_group` in A01: 20/7 with the original seed.
Grouping preceded assignment. The sparse family distribution is retained unchanged;
both SQL cases landed in holdout and all access-control cases in development.
No selection/rebalancing used scanner output, model output or benchmark scores.

Reviewer status is `single_reviewer_pending_independent_review`: Codex traced source
flows and reviewed their anchors/remediation boundaries. No second human review or
runtime proof is claimed. A04 must review/freeze the final evaluated scope, including
how detection-only cases and environment guards affect that scope. `other` exclusions
are explicit deferred reviews, not assertions that the application is safe.
