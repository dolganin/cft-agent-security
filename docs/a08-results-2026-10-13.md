# A08: исходные метрики CFT Security Agent на Juice Shop

13 октября 2026. **A08 завершен с явно указанными ограничениями измерений.**
Это исходный замер до улучшения поиска, не отчет об успешном достижении высоких метрик.

## Итог

На фиксированном эталоне Juice Shop v20.2.0 агент обнаружил четыре из 27
положительных случаев и доказал три: SQL-инъекцию поиска, SQL-инъекцию входа
и раскрытие списка чувствительных файлов `/ftp`. Это счетчики случаев,
а не основной объединенный показатель: метрики DEV и HOLDOUT считаются отдельно.

Показан один завершенный запуск агента, длительность 536,531 секунды
(8 минут 57 секунд), 46 успешных запросов Qwen3.8-27B. Три ранние попытки
остановились на отсутствии Semgrep до работы модели и исключены из security-метрик.

Агент пока не расширил множество найденных случаев относительно SAST baseline.
Он добавил доказательства для трех находок. Основные проблемы: узкое обнаружение,
ошибка семейства у MD5 и отсутствие конечного доказательства для редиректа.

## Метрики, запрошенные для ТЗ

Знаменатели: DEV original содержит 20 положительных и два отрицательных случая;
HOLDOUT original содержит семь положительных и шесть отрицательных.

| Метрика | DEV / original | HOLDOUT / original |
| --- | --- | --- |
| Precision среди доказанных confirmed | N/A: 0 подтверждений | 3/3 = 100% |
| Recall доказанных confirmed | 0/20 = 0% | 3/7 = 42,86% |
| False positive rate | 0/2 = 0% | 0/6 = 0% |
| Точность доказанного бинарного вердикта | N/A: 0 решений | 3/3 = 100% |
| Покрытие доказанными бинарными решениями | 0/22 = 0% | 3/13 = 23,08% |
| Доля случаев без доказанного решения | 100% | 76,92% |
| Точность серьезности | N/A | N/A: оценено 0 из 4 размеченных случаев |
| Точность Context Priority | N/A: нет эталонных оценок | N/A: нет эталонных оценок |
| MTTR | N/A | N/A |
| Воспроизводимость между запусками агента | N/A: один завершенный запуск | N/A: один завершенный запуск |

Precision 100% рассчитан всего по трем размеченным подтверждениям, а не по всем
обнаруженным проблемам. Четвертый confirmed, список файлов `/encryptionkeys`,
находится вне эталона и не считается автоматически ни TP, ни FP.

FPR 0% означает отсутствие ложных confirmed на размеченных отрицательных
случаях. Агент не выдал ни одного доказанного rejected; все восемь original
контролей остались not_detected. Поэтому это не доказательство надежного
распознавания безопасного кода. Точность вердикта 100% относится только к
отвеченным случаям; на 35 original-случаях всего три доказанных решения.

MTTR не измеряется: данный этап не исправляет уязвимости и не содержит
зафиксированных времен устранения. N/A не заменяется временем анализа.

## Сравнение с SAST/DAST baseline

Baseline выполнялся три раза. Все 18 показателей по слоям/срезам повторно
пересчитаны из переданных нормализованных наблюдений и совпали с исходными
scorecard. DEV/HOLDOUT и обнаружение/подтверждение не смешиваются.

| Система | Detection Recall DEV | Detection Recall HOLDOUT |
| --- | --- | --- |
| SAST baseline, каждый из трех запусков | 1/20 = 5% | 3/7 = 42,86% |
| DAST baseline, каждый из трех запусков | 0/20 = 0% | 1/7 = 14,29% |
| SAST + DAST, каждый из трех запусков | 1/20 = 5% | 3/7 = 42,86% |
| Агент A07, один запуск: обнаружение | 1/20 = 5% | 3/7 = 42,86% |

SAST находит редирект, `/ftp` и обе SQL-инъекции. DAST находит поисковую
SQL-инъекцию, уже найденную SAST. По этим размеченным случаям прирост обнаружения
при добавлении DAST или агентной части равен нулю.

Baseline и агент имеют разные конфигурации: 310 SAST-правил плюс DAST против
двух demo-правил плюс Scout. Сравнение не изолирует эффект LLM или контекстного
скоринга. Нельзя приписать различия одной только агентной проверке.

На baseline стабильны множества размеченных обнаружений: одинаковы во всех
трех запусках; Jaccard по непустым множествам равен 1 (для пустого DAST DEV N/A).
Это не стабильность всего
сырого вывода: SAST вернул 94/94/75 наблюдений, DAST 409/405/412.

## Карта проблем и приоритеты следующего этапа

| Наблюдаемый результат для 27 положительных случаев | Число |
| --- | --- |
| Подтверждено с Evidence | 3 |
| Есть кандидат, но семейство не совпало с эталоном: MD5 | 1 |
| Обнаружено, но конечного Evidence нет: редирект | 1 |
| Нет кандидата, хотя Scout прочитал полный закрепленный anchor | 4 |
| Нет кандидата и нет полного прочитанного anchor в журнале Scout | 18 |

В четырех прочитанных случаях три содержат прочитанный основной sink, а один
(JS-FILE-002) только helper: это не четыре полностью разобранных потока данных.
Категории показывают место потери в журнале, не доказанную внутреннюю причину
решения модели. Построчные данные всех 41 случаев находятся в `case-losses.csv`.

Дальше, в этапе B:

1. Нормализовать семейства кандидатов до проверки: MD5 сейчас ошибочно назван
   authentication вместо weak-cryptography. Эталон и прошлые цифры не менять.
2. Расширить реальный обзор кода и SAST. Scout прочитал пять файлов, остановился
   после двух ходов и предложил четыре кандидата; это не полноценный поиск.
3. Добавить Evidence-backed проверки редиректа и следующих семейств. Чтение
   исходников само по себе не доказывает эксплуатируемость.
4. Проверить отрицательные случаи реальными решениями rejected, включая
   отдельное исполнение patched/synthetic контролей.
5. Повторить замер на новой замороженной конфигурации; отдельно оценивать
   обнаружение, подтверждение и оценки серьезности/контекста.

## Ограничения и воспроизведение

- Эталон не исчерпывает Juice Shop. HOLDOUT публичен и ранее частично изучался;
  это не доказательство качества на неизвестных проектах.
- Один успешный запуск агента, не три. Межзапусковая устойчивость не измерена.
- Два patched и четыре synthetic контроля в A07 не исполнялись. Их отсутствие
  в находках нельзя считать шестью успешными безопасными проверками.
- Три снимка исходников A06 `sast/source.tar` не переданы. Остальные файлы
  проверены по seals; пересчет доступных наблюдений воспроизводим. Полная
  проверка исходных A06 пакетов не выполнена.
- Все четыре A07 seals проверены полностью. Все четыре confirmed проверены по
  сохраненным execution/audit/trace; активная перепроверка target не проводилась.
- Ни один вывод не требует изменения эталона или скрытого исключения пропусков.
