## Короткий вывод

Агент действительно работал с моделью и выполнил проверки. Но обнаружение пока
узкое: из 27 положительных случаев эталона обнаружены четыре, доказаны три.
Те же четыре случая обнаружены SAST baseline во всех трех сохраненных запусках.
Прирост обнаружения на размеченном наборе в этой конфигурации не показан.
Польза агентной части здесь состоит в получении Evidence для трех случаев,
а не в расширении покрытия эталона.

Это результаты фиксированного ограниченного набора Juice Shop v20.2.0,
а не доля всех уязвимостей Juice Shop. DEV и HOLDOUT ниже разделены.
Сводные 4/27 и 3/27 используются только как инвентаризация случаев,
не как основной усредненный показатель.

| Показатель | DEV / original | HOLDOUT / original |
| --- | --- | --- |

| Доля случаев без доказанного бинарного решения | 22/22 = 100% | 10/13 = 76,92% |

100% Precision относится только к трем сопоставленным подтверждениям.
Внеэталонные находки не считаются автоматически ни TP, ни FP. Нулевой FPR
не доказывает способность отвергать безопасные случаи: ни одного доказанного
`rejected` нет, все восемь original-контролей остались `not_detected`.
Точность на отвеченных случаях нужно читать вместе с низким покрытием.

Шесть patched/synthetic-контролей имеют отдельные scorecard, но в этом запуске
не обнаружены и не получили бинарных решений. Их нельзя выдавать за шесть
успешно выполненных отрицательных runtime-тестов или прибавлять к основному
знаменателю original FPR. Проверка исполнения этих контролей остается задачей
финального разбора A08.

индивидуальным объяснением каждого из 23 пропусков. Дальше нужна карта по case_id.

## Первое сравнение с A06

По переданным scorecard все три baseline-запуска имеют одинаковые множества
сопоставленных original-случаев:

| Конфигурация | DEV: найдено из 20 | HOLDOUT: найдено из 7 |
| --- | --- | --- |
| SAST baseline, каждый из трех запусков | 1 | 3 |
| DAST baseline, каждый из трех запусков | 0 | 1 |
| Объединение SAST + DAST, каждый из трех запусков | 1 | 3 |
| Агент A07: обнаружение, один запуск | 1 | 3 |
| Агент A07: доказанные подтверждения, один запуск | 0 | 3 |

SAST обнаруживает редирект, `/ftp` и обе SQL-инъекции; DAST сопоставлен только
с поисковой SQL-инъекцией JS-SQL-001. Прирост множества найденных случаев
при добавлении DAST или агентной части здесь равен нулю. Для выводов о причинах
нужны отдельные разборы происхождения кандидатов и возможностей проверок.

Системы не имеют одинаковой конфигурации: baseline использует широкий пакет
310 SAST-правил и DAST, агент — два demo-правила плюс Scout. Это сравнение
фактических систем, не контролируемое измерение эффекта одного только LLM.
Baseline detection нельзя назвать Precision/Recall подтвержденных вердиктов.

Raw-находки A06 меняются: SAST 94/94/75, DAST 409/405/412.
Поэтому совпадение четырех размеченных случаев не означает совпадение всех
raw-находок. Время A06: 229,844 / 238,016 / 265,203 секунды. A07: 536,531 секунды.
По одному запуску агента нельзя утверждать стабильную разницу времени.
Полная офлайн-проверка A06 ограничена отсутствующими снимками исходников.

## Как воспроизвести локальный пересчет A07

Используется ветка `codex/a08-initial-analysis` с переносимым чтением путей.
Путь Windows ниже — исторический корень переданного пакета, не локальный target.

```bash
PYTHONDONTWRITEBYTECODE=1 CFT_AGENT_MODE=stub .venv/bin/python -m evaluation.offline_rescore \
  --dataset benchmarks/juice-shop-v20.2.0-v2/ground_truth.yaml \
  --artifacts artifacts/a08-handoff-2026-10-13/artifacts/a07-series/agent-run-01-retry-01 \
  --output artifacts/a08-analysis-2026-10-13/a07-relocated-rescore \
  --run-id a08-imported-a07 \
  --original-pipeline-root 'C:\Users\User\Documents\GitHub\cft-security-agent\artifacts\a07-series\agent-run-01-retry-01\pipeline'
```

Для нового повторного расчета выбрать новый output, чтобы сохранить предыдущий.
Ни Docker, ни LLM, ни сканирование target для этого расчета не требуются.
