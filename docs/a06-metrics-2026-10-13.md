## Matching correction

Real ZAP reported SQL injection in GET `/rest/products/search` parameter `q`.
A04 names the input `query.q`. Literal parameter comparison missed this observation.
The corrected A05 scorer accepts the bare query name for GET/HEAD only, retaining
method checks and rejecting unknown or explicitly body-qualified mismatches.
Positive and negative regressions cover GET, POST, body qualification and missing
parameter. This does not change labels or add a vulnerability after measurement.

Scorer commit: `3942bad99d2007d0ceaaf83b533594eb8b1dc2a0`.
Scorer source SHA-256:
`7b47607a7f68f7e6b61c8053c0cd8adc81a3e35539e4d56fe46e318c058f8f61`.
Before the correction DAST had zero matched positives; after it has one. The
saved raw scanner observation and frozen anchor are unchanged.

No three-run scanner stability or statistical generalization claim is made.

limitations); they do not reduce denominators. ZAP completed its bounded stages,
but anonymous access does not test cross-user business logic or privileged flows.

vocabulary differences (e.g. generic authorization vs access-control, xxe vs the
expanded XML family) are integration coverage limits, not proof that scanners
cannot discover those classes. Freeze a new configuration if changing the adapter.

## Recompute without scanner/LLM calls

```bash
PYTHONPATH=. .venv/bin/python scripts/rescore_a06_slices.py \
  --artifacts artifacts/a06/2026-10-13-attempt-001 \
  --output artifacts/a06/a-fresh-score-directory
```

This checks the input seal, current A04/A06 locks and manifest bindings, scores
each original split separately, and refuses an existing/overlapping destination.
The frozen A06 legacy score command expects an older unsliced A05 API; this
explicit wrapper avoids pooling splits without editing the frozen scanner code.
Local outputs: `artifacts/a06/2026-10-13-scores/` and
`artifacts/a06/2026-10-13-scores-repeat/`, six scorecards plus summary each.
