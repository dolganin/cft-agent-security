## Установка

Репозиторий клонирован по HTTPS из GitHub в новый каталог. Созданы новая
Python 3.11.9 `.venv`, отдельные кэши pip/npm и новая база API. Зависимости
установлены командами из README с `requirements-first-run.txt` и npm lockfile.
Из рабочей конфигурации передан только действующий NSU-ключ как операторский
ввод; старые `.env`, база, артефакты, checkout Juice Shop и ручные правки кода
в новую копию не переносились. Обновления получены обычным Git pull.

GitHub-доступ был предоставлен существующим авторизованным аккаунтом через
отдельную тестовую конфигурацию Git. Регистрация нового аккаунта не имитировалась.
Стандартные порты заняты другими приложениями, поэтому использован описанный
в инструкции вариант 8082/8091/5174. Их процессы не останавливались.

`app.setup --prepare-demo` и проверка живой модели завершились успешно.
Диагностика стандартного занятого порта отдельно вернула понятную ошибку и код 2.
Это ожидаемая проверка сообщения об ошибке, а не успешный запуск на занятом порту.

Пропуски относятся к отдельно включаемым интеграциям и отсутствующим историческим
фикстурам. Они не засчитаны как пройденные проверки.
Во время проверки исправлены относительные пути правил Semgrep, совместимость
старого теста с закрепленной версией Ruff и обработка медленного Docker probe
при сборе необязательных интеграционных тестов.

## Данные и границы

[Пакет результатов](../../artifacts/handoffs/readme-chat-cli-ci-2026-11-15.zip)
содержит результаты CLI/UI/CI, команды проверки, логи и снимки интерфейса.
[SHA-256 архива](../../artifacts/handoffs/readme-chat-cli-ci-2026-11-15.zip.sha256).
Внутри находятся `acceptance.json`, `execution.json` и `manifest.sha256.json`;
все контрольные суммы проверены после создания архива. Конфигурация с ключом,
база API, виртуальное окружение и `node_modules` в архив не входят.

Это приемка контролируемого учебного магазина и инструкции установки, а не
оценка полноты на произвольном проекте или новый замер Juice Shop.
Полный сценарий проверен локально на macOS и в CI на Ubuntu. Нативная Windows
и полный UI-проход в WSL отдельно не выполнялись.

Структура README ориентирована на короткий вход и разделение сценариев в
[Aider](https://github.com/Aider-AI/aider),
[Trivy](https://github.com/aquasecurity/trivy) и
[Open WebUI](https://github.com/open-webui/open-webui).
