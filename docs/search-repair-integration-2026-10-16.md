# Совместная версия поиска и исправлений

Ветка `codex/juice-c-metrics-integration` объединяет фактическую локальную версию
поиска/проверок с `origin/main` на `35e3979` (C01–C05). Исходные рабочие копии
сохранены. Единственный merge-конфликт был в AGENTS.md: обе части документа
сохранены, разделы C перенумерованы без изменения требований.

## Один свежий проход

```bash
python -m app.single_pass_measurement \
  --checkout artifacts/benchmark-target/juice-shop \
  --output artifacts/single-pass-search-and-repair-NEW \
  --image sha256:73fd92a20ad72cf189bfcda4604196b8476dfad07c54bbf06ec830e3ec0fa7e7 \
  --browser-image sha256:2f553e84f1e6fbccd51a5d5d7efa7af8c4dbe63a202c60efd830c0b9b62b05ea \
  --fix-image cft-fix-juice:stage1
```

Ключ NSU поступает через окружение или локальный .env. Опциональный `--env-file`
выбирает существующую локальную конфигурацию. Ключ не записывается в артефакты.

Перед измерением проверяются модель, закрепленный target, эталон, инструменты
и образы. Выполняется один полный research diagnostic с расширенным SAST и
зарегистрированными проверками. Затем результаты независимо пересчитываются
по A04. Поиск имеет прежний общий HTTP-лимит 2048 и бюджет до 1800 секунд.

Оценщик выбирает только два уже поддерживаемых C01 семейства, если соответствующие
случаи получили доказательное подтверждение в новом поиске. Для каждого запускается
одна C04 кампания, максимум одна LLM-попытка и 900 секунд рабочего бюджета.
Исторический фиксированный шестислотовый C05 протокол не изменяется и не запускается.

C04 продолжает использовать защищенные C01/B09 входы на том же исходном commit.
Новые case/evidence-записи связывают допуск случая к исправлению с новым поиском,
но не подменяют C01/B09 отчет внутри C04. Во время проверки C03 заново воспроизводит
BEFORE и AFTER в изолированных копиях. FIXED требует независимого replay,
успешных обязательных тестов, сохранности оригинала и очистки.

`metrics.json` содержит все исходы, длительности, текущие подтверждения и причины
неуспехов. Таймер лабораторного исправления начинается при допуске уже подтвержденного
случая, заканчивается после C04/C03 replay и включает очистку. Неуспехи не имеют
времени устранения, но сохраняют фактическую длительность. Эксплуатационный MTTR
и воспроизводимость не заявляются. Отдельная сводка не меняет оригинальный Gate.

## Пересчет уже сохраненных результатов

```bash
python -m app.delivery_metrics \
  --search-run /path/to/sealed/research-run \
  --output artifacts/bespalov-delivery-NEW
```

Этот CLI объединяет один сохраненный поиск и отдельную историческую C05 серию.
Он перепроверяет execution/audit поиска, пересчитывает DEV/HOLDOUT по количествам,
проверяет SHA256 публичной C05 проекции, независимо проигрывает три полных SQL
архива и сверяет арифметику всех шести строк. Полные исходные redirect-артефакты
в публичной проекции отсутствуют; поэтому полный replay шести исправлений
помечается недоступным. `--repair-series <полный-пакет>` включает полный replay,
если пакет предоставлен.

Исторический A06 baseline приводится отдельно (один сохраненный запуск на том же
original-эталоне). Новая версия имеет расширенные правила SAST и иной доступ
к target; сравнение таких конфигураций не является контролируемой абляцией.

Точность серьезности/CP остается N/A, если запуск не содержит совместимых оценок
или эталон не имеет независимых CP labels. Неопределенные и непроверенные случаи
сохраняются в знаменателе Recall и покрытии решений.
