# B09: один реальный сквозной замер, 15 октября 2026

## Итог

Завершен один валидный ограниченный сквозной запуск на Juice Shop v20.2.0.
Найдено 13 из 27 уязвимых случаев эталона, подтверждено 5 из 27.
В историческом валидном запуске A07/A08 было найдено 4 и подтверждено 3.
Прирост поиска есть, но полнота подтверждения остается низкой. Это не агент,
который обнаруживает почти все уязвимости Juice Shop.

По прямому решению заказчика выполнен один итоговый запуск вместо трех.
Воспроизводимость не измерялась. Предшествующая интеграционная попытка сохранена
как невалидный замер, а не как второй успешный прогон.

## Зафиксированная конфигурация

- Цель: commit `5658473cf8814459bf89000ce373b20ed0b4eb37`, 1300 неизмененных tracked файлов.
- Реализация запуска: `149759a`; настройки сохранены в `run-config.json`.
- Модель: `nsu:qwen3.8-flash-next`, reasoning low, без внешнего fallback.
- Расширенный SAST B02; Scout B03: 8 шагов, 160000 символов, до 32 кандидатов.
- Проверка одной находки: до 2 итераций и 120 секунд.
- Только существующие операторские профили B01, B05 и B06; существующие Validator,
  Executor и Evidence. Эталонные ответы не передаются производящему контуру.
- Продолжительность итогового запуска: 284.586 секунды, примерно 4 минуты 45 секунд.
- CI завершился с exit 1: это обнаруженный риск безопасности, не техническое падение.

Профили, политики, схемы и исторические результаты A01-A08 не переписывались.
Единственный общий дефект интеграции: Discovery терял операторские
`verification_routes`, `access_fixture` и `b06_verification`. Исправление сохраняет
эти поля из доверенного профиля. Проверки соответствия снимков не ослаблялись.

## Что именно измерялось

Замороженный A04 `ground_truth.yaml`, только `sample_kind=original`:
DEV: 20 уязвимых + 2 безопасных случая; HOLDOUT: 7 уязвимых + 6 безопасных.
Итого 35 случаев, включая 27 уязвимых. Это выбранный эталонный набор,
не полный список учебных challenges Juice Shop. Patched/synthetic здесь не запускались.

DEV и HOLDOUT оценены отдельно неизмененным matcher A05. Общие числа ниже
являются описательной суммой двух срезов, а не новым независимым holdout.
Исторический HOLDOUT уже использовался командой: этот отчет не доказывает
обобщение на совершенно неизвестный проект.

## Метрики

| Показатель | DEV | HOLDOUT | Общая описательная сумма |
|---|---:|---:|---:|
| Найдены уязвимые случаи | 10/20, 50% | 3/7, 42.86% | 13/27, 48.15% |
| Recall по подтвержденным | 2/20, 10% | 3/7, 42.86% | 5/27, 18.52% |
| Precision подтверждений внутри эталона | 2/2, 100% | 3/3, 100% | 5/5, 100% |
| Ложные подтверждения / безопасные случаи | 0/2 | 0/6 | 0/8 |
| Точность среди выданных бинарных вердиктов | 2/2 | 3/3 | 5/5 |
| Покрытие бинарными вердиктами | 2/22, 9.09% | 3/13, 23.08% | 5/35, 14.29% |

Precision здесь условный: только для подтверждений, сопоставленных с размеченным
эталоном. Внеэталонная находка не объявляется автоматически истинной или ложной.
Пять правильных решений при 30 воздержаниях нельзя представлять как 100% качества агента.

`false_confirmation_rate` вычислен по действующему протоколу как ложные
подтверждения / все безопасные случаи. Все восемь безопасных случаев остались
без бинарного вердикта. Поэтому 0/8 не доказывает высокую специфичность на
активно проверенных отрицательных примерах; классический FPR среди решенных
отрицательных случаев здесь не оценен.

Точность severity: N/A, 0 оцененных совместимых значений. Для HOLDOUT есть
4 размеченных ordinal severity, но в этом запуске нет принятых операторских
ScoringReview для сравнения с ними. CVSS нельзя сравнивать с этой шкалой.
Точность Context Priority: N/A, независимых CP-меток в A04 нет.
MTTR: N/A, исправления в этом замере не выполнялись.
Воспроизводимость: N/A, один итоговый запуск.

| Контур | DEV: найдены / подтверждены | HOLDOUT: найдены / подтверждены |
|---|---:|---:|

| Новый SAST B02, сырые сигналы текущего запуска | 7/20 / не измеряется | 3/7 / не измеряется |
| Новый SAST + Scout + проверка | 10/20 / 2/20 | 3/7 / 3/7 |

Scout добавил 3 обнаруженных уязвимых случая относительно нового SAST,
а доступные runtime-проверки добавили два подтвержденных класса: redirect и
смена собственного пароля без обязательной повторной аутентификации.
На HOLDOUT прироста относительно старого запуска нет.

Исторический A06 DAST обнаруживал 0/20 DEV и 1/7 HOLDOUT. Его запечатанные
scorecards приложены только как историческая справка. Новый DAST не запускался;
его результаты нельзя называть повторенным B09 baseline. Новый SAST baseline
взят из сырых результатов этого же запуска, до Scout и агентной проверки.
Модель, правила и workflow изменились одновременно: сравнение не изолирует
вклад каждого изменения как контролируемый эксперимент.

## Почему результат пока невысокий

- 95 сигналов SAST + 23 принятых кандидата Scout; 3 дубля Scout, 20 новых.
  После объединения 115 наблюдений, а не 115 независимых уязвимостей.
- Scout просмотрел 44 файла, 3137 из 20861 проиндексированных строк: 15.04%.
  Остановился по бюджету исходников. Это ограниченный поиск, не полный аудит.
- Semgrep: 59 известных предупреждений покрытия, без фатальных диагностик.
- Из 27 положительных случаев 14 не найдены, 8 найдены, но не имеют
  результативной доступной проверки. Они не исключены из знаменателя Recall.
- B05 write-v3 еще не принят; код-evaluation в закрепленном Docker ограничен
  safe mode. Не включали отключенные ветки ради лучшей цифры.
- Приоритет дальнейшей работы: подтверждение уже найденных access-control,
  SSRF, XXE, NoSQL и traversal; затем расширение покрытия пропущенных семейств.
  Отдельно нужны отрицательные контроли, на которых агент действительно выдает rejected.
