Дата: 15 октября 2026. Ветка: `codex/juice-shop-plan-recovery`.

## Что изменилось

- Рабочая копия из `/private/tmp` исчезла. Успешные изменения восстановлены
  из журнала в постоянную копию `/Users/stavrmoris/cft-security-agent-j01-j10`.
  Прежние временные runtime-артефакты не восстановлены: ниже используются новые
  измерения, а исторические записи плана не выдаются за доступные доказательства.
- Добавлен отдельный source-only producer. Он читает разрешенную проекцию
  исходников, сохраняет точные anchors и provenance; не читает ответы эталона,
  не устанавливает `confirmed`, severity или разрешения на выполнение.
- Его кандидаты входят в общую очередь отдельно от SAST и модели. Исправлена
  идентичность NoSQL, ранее ошибочно попадавшая в SQL по совпадению подстроки.
- Глобальная HTTP-квота отделена от квоты одного проверочного окружения:
  1024 на campaign, не более 256 на отдельный runtime. Проверки по-прежнему
  проходят Validator, Executor и независимую проверку Evidence.
- B05 binding теперь охватывает AST-тело зарегистрированных функций, а не
  только строку объявления. Реальные находки внутри тела получают корректную
  привязку без расширения целевого сервиса или разрешений модели.
- Добавлен явный `--verification-only`: он не создает LLM-клиент и не считается
  полным исследовательским прогоном. Отчеты и ограничения сохраняются даже
  при отсутствии исследовательских вопросов.

`5658473cf8814459bf89000ce373b20ed0b4eb37`. A04 и его matcher не изменялись.
Результаты: `artifacts/juice-source-development-v3-2026-10-15` и
`artifacts/juice-source-score-v3-2026-10-15`.

| Производитель | Найденные положительные случаи | Покрытие |
|---|---:|---:|
| SAST этого запуска | 10/27 | 37.04% |
| Новые source detectors | 17/27 | 62.96% |
| Объединение | 27/27 | 100% |

41 source-кандидат и 98 адаптированных SAST observations не означают столько
уникальных уязвимостей. Семейства, повторные наблюдения и anchors сопоставлены
неизменным оценщиком. Целевой исходник остался неизменным.

Один source-кандидат оценщик классифицирует как alert на безопасном
`JS-SAFE-BIZ-101`. Сигнал об отсутствии нижней границы количества пересекается
с проверкой верхней границы склада. Это не `confirmed`, но и не нулевой шум:
кандидат оставлен в отчете. Безопасность остальных случаев не доказана простым
отсутствием alert; это не позволяет объявить runtime FPR равным нулю.

100% здесь означает только обнаружение на известном разработчикам наборе из
27 положительных случаев. Это не подтвержденный Recall, не все задания
Juice Shop и не качество на неизвестных проектах. Исторический HOLDOUT уже
используется для разработки; независимым holdout он больше не является.

## Что еще не закрыто

Новые source-сигналы не заменяют J05–J08 runtime-протоколы. Необходимы
независимые controls и фиксированные проверки для оставшихся направлений,
включая доступ/роли, NoSQL, SSRF, XXE, traversal, XSS и бизнес-логику.
Code evaluation остается unsupported на закрепленном Docker runtime.
Нужно проверить безопасные случаи реальными отрицательными решениями,
закончить J09 и только затем выполнить один согласованный полный J10 run.
MTTR, независимая воспроизводимость, severity accuracy и CP accuracy пока N/A.

## Офлайн-пересчет

Из корня checkout с установленными dev-зависимостями:

```bash
python -m evaluation.juice_source_progress \
  --run artifacts/juice-source-development-v3-2026-10-15 \
  --output artifacts/juice-source-score-replayed
```

Выходная папка должна быть новой. Scorer проверяет seals и frozen A04 перед
расчетом. Docker, модель и API-ключ для этого пересчета не нужны.

Runtime-оценка сохраненных доказательств также пересчитывается без Docker:

```bash
python -m app.research_score \
  --run artifacts/juice-fixed-source-acceptance-retry-3-2026-10-15 \
  --output artifacts/juice-fixed-score-replayed
```
