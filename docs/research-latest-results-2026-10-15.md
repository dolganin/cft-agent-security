# Последние изменения и результаты перед оптимизацией Juice Shop

Дата: 15 октября 2026. Цель: Juice Shop v20.2.0,
commit `5658473cf8814459bf89000ce373b20ed0b4eb37`.
Эталон: frozen A04 original, 27 уязвимых + 8 безопасных случаев.

## Опубликованная реализация

- Opt-in исследовательский контур R00–R09: чтение исходников, поиск, рабочие
  файлы и Python/Node-скрипты в Docker, HTTP и браузерные наблюдения.
- Общие ограничения вызовов/действий/IO/времени, checkpoints и сохранение
  частичных результатов, транспорт модели с полным дедлайном запроса.
- Подключение существующих канонических B01/B05/B06 проверок с независимыми
  Validator/Executor/persisted Evidence; model stdout не становится вердиктом.
- Отдельный route-exact grant для фиксированной четырехзапросной SQL/login
  проверки. Он не дает модели произвольный POST.
- Отдельные surface questions для файлов с SAST findings. Исходники существующих
  операторских маршрутов имеют приоритет при заполнении реестра из 64 файлов.
- `app.research_score`: offline-пересчет исследовательского запуска на неизменном
  A04 matcher с повторной проверкой approval, execution/audit и runtime Evidence.

R09: DEV найдено 7/20, confirmed 1/20; HOLDOUT найдено 3/7, confirmed 2/7.
Совокупный detection recall 37.04%, runtime-confirmed recall 11.11%.
Precision подтверждений внутри эталона 3/3 = 100%, покрытие бинарными ответами
3/35 = 8.57%. False-confirmation rate 0/8, но все безопасные случаи без бинарного
ответа; классический FPR по решенным отрицательным случаям не оценен.
Severity/CP accuracy, MTTR и воспроизводимость — N/A.

11 runtime-подтверждений R09 сводятся к SQL/login, SQL/search и redirect;
остальные восемь — дубли. Две AST-проверки MD5 относятся к одной source-condition
и не включены в runtime Recall. SAST текущего запуска уже покрывал те же 10/27
случаев; измеренного прироста от исследовательского контура нет.

R09 остановился по бюджету: 44 вопроса, 251 модельный вызов, 175 действий;
57 вопросов оставались pending. Два вопроса завершились ошибками схемы ответа,
один — исчерпанием коррекций. Это degraded development diagnostic, не чистая
приемка. Из 41 передачи на проверку 30 остались pending. Текст модели и
несопоставленные гипотезы не были вручную превращены в TP.

Потеря FTP в расширенном B09 вызвана заполнением реестра исходников до `server.ts`.
Исправление приоритета регистрации проверено отдельно: Docker acceptance 6/6
(SQL search/login и FTP до/после сдвига строк), integrity и cleanup passed.
Исторические метрики после исправления не переписаны.

и не переопределяют исторические A01–A08/B09 результаты.
