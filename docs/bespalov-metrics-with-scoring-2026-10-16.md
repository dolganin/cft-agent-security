# Метрики Juice Shop с дополнением по серьезности

Один свежий проход, Juice Shop v20.2.0, original-срез A04: 27 уязвимых и 8 безопасных
случаев. Поиск и два исправления измерены 16 октября; серьезность дополнительно
рассчитана офлайн по сохраненным доказательствам, без нового поиска. CP дополнен
расчетом для заявленного сценария и отдельной слепой модельной разметкой.

| Метрика | Результат |

| Precision подтверждений по эталону | 13/13 = 100% |
| Recall подтверждений | 13/27 = 48,15% |
| Ложные подтверждения безопасных случаев | 0/8 = 0%; среди решенных безопасных случаев FPR N/A |
| Точность вынесенных бинарных вердиктов | 13/13 = 100%, покрытие решениями 13/35 = 37,14% |

Оценка серьезности использует доказанные свойства: приобретение административной
роли, несанкционированное постоянное изменение товара и обход аутентификации.
Все три получили HIGH и совпали с существующей A04 разметкой. Четвертый размеченный
случай, SQL injection в поиске, оставлен UNASSESSED: имеющееся differential Evidence
не устанавливает достаточный ущерб для поддерживаемой рубрики.

Это **не точность CVSS и не качество оценок LLM из исходного запуска**. Новая функция
детерминированно оценивает уже доказанные свойства. Все четыре существующие метки
серьезности - HIGH; такой маленький одноклассовый срез не показывает способность
классифицировать разные уровни серьезности на широком наборе. У остальных случаев
нет эталонной разметки серьезности; они не объявляются LOW.

Для CP пользователь задал сценарий публичного магазина с реальными аккаунтами
и заказами. Новый постфактум-расчет сохраняет неизвестные факты и выставляет
уровень только при его устойчивости ко всем их допустимым значениям. Отдельный
модельный рецензент оценил source anchors без доступа к результатам агента или
его scoring-формуле. Это черновик, требующий человеческой проверки, а не готовый
эталон: **55% нельзя называть человечески подтвержденной точностью CP**.
Текущая формула почти всем backend-находкам дает HIGH и плохо различает их impact.
В исходном проходе 31 CP-отчет partial, 15 отсутствуют; эти исходные оценки не
переписаны. Сценарная оценка не описывает реальную публичность Docker-стенда.

Precision 100% ограничен подтверждениями, сопоставленными эталону. Находки вне
эталона не считаются автоматически ложными. Безопасные случаи не получили
бинарных решений, поэтому нулевое число ложных подтверждений не доказывает их
успешное отклонение. Исследование остановлено по бюджету, содержит ошибки отдельных
вопросов и имеет статус completed_with_limitations. Корпус известен разработчикам.

Исторический baseline имеет другие правила, бюджеты и анонимную DAST-роль; это
сравнение конфигураций, не чистая абляция одного агента. Два исправления проверены
через fresh BEFORE confirmed, AFTER rejected, обязательные build/functional/security
gates, original integrity и cleanup. Для redirect две устаревшие native assertions
учитываются защищенным C03 contract; raw failures сохранены. Времена не включают
отдельные 1845,308 с поиска и не описывают исправление всех 13 подтверждений.
